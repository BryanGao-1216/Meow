# 喵喵备忘录

菜单栏或小猫右键菜单中的“喵喵备忘录…”打开编辑器。每条记录有任务、明确时间和待办/完成/取消状态；可以新增、改时间、完成、取消、稍后十分钟、删除及查看已结束记录。界面和聊天使用同一个控制器、同一个本机文件。

对话例子：

- “明天晚上七点提醒我参加聚会。”
- “把聚会改到明天晚上八点。”
- “买猫粮已经完成了。”
- “取消参加聚会的提醒。”
- “我有哪些备忘录？”

聊天操作由 LLM 解析为受约束的 JSON。只接受真实任务编号与携带时区的未来时间；含糊的早晚、缺少任务、重复名称无法确定目标、循环规则等会先追问，不偷偷猜测。请求由本机执行并原子保存成功后，才向角色模型提供已验证结果并确认。故事和引用不会只因为含有“提醒”就创建任务。普通闲聊不额外调用备忘录规划模型；模型也被明确禁止在没有工具结果时声称已经设置提醒。

## 两种提醒

到点提醒：每五秒检查一次未通知的到期任务，优先交给 LLM 判断任务范围并生成 Meow 口吻的提醒。到点任务不得被模型随意跳过，提前提醒也不代替到点提醒。模型输出无效或网络失败时保留任务，至少间隔一分钟重试，界面显示原因。需要等待当前聊天、拖拽或气泡结束；小猫睡觉时，到点闹钟可以唤醒它，但不解除贴墙。

提前提醒：启用后，每隔半小时把当前备忘录、允许提醒的任务、最近提醒记录和记忆中的偏好交给 LLM，决定是否值得现在打扰以及具体说什么。例如七点的聚会，可以在五六点考虑准备或出门。没有需要就保持安静。对同一任务至少间隔一小时，每个时间版本最多三次提前提醒，防止反复催促；到点提醒不受这个限制。关闭“让 Meow 主动提前提醒”只关闭这一通道，到点闹钟照常运行。小猫睡觉、聊天或被拖动时，提前判断会等待。

全部提醒文案来自 LLM，失败时不会用固定台词伪装成功。功能复用已配置的火山引擎云端模型；聊天设置通常增加一次规划请求，再由正常对话生成确认。每轮巡看或到点提醒通常使用一次结构化模型请求。备忘录存在任务时才巡看，重启恢复上次巡看时间，避免通过重启反复请求。

## 可靠性与数据

存储位置：`~/Library/Application Support/Meow/meow-memos.json`，与长期记忆小本本分开。包含任务、巡看时间、已生成待发送的提醒、已投递记录和重试时间。采用原子写入及仅本人读写的文件权限，损坏文件不会自动覆盖，界面提供重试读取。修改时间会清除该任务旧的提醒标记。

提醒先持久化到待发队列，实际显示气泡并写入聊天记录后才标记已通知；重启会恢复待发任务。生成期间如果主人修改、完成、取消或删除任务，旧异步结果不得回写。提前提醒过了有效期或任务到点时会丢弃旧文案，重新处理到点提醒。慢速的提前判断不会阻塞到点任务。

需要 Meow 运行、电脑唤醒、云端配置可用并联网。应用退出和系统休眠时不会在后台发出提醒，恢复后会补上未通知的到点任务；恢复网络后重试。进程恰在展示与保存通知标记之间被强制终止时，恢复后可能再次补提醒，不能提供跨进程崩溃的严格恰好一次保证。

参考了本地 [Mochi 的提醒数据管理](../vendor/Mochi/app/reminders/manager.py)、[定时检测](../vendor/Mochi/app/reminders/scheduler.py)、[展示适配](../vendor/Mochi/app/reminders/notifications.py) 和 [主动交流策略](../vendor/Mochi/app/ai/initiative.py) 的分层；重新实现为 Swift 模块。Mochi 的主动策略并未接入日历轮询，这里的半小时 LLM 巡看为 Meow 新增。没有复用其“忽视后生气”的固定催促逻辑。

## 开发检查

```sh
.build-cloud/release/Meow --selftest --unit-only
.build-cloud/release/Meow --memo-render-check /tmp/meow-memo-preview
```

自检注入假时钟、假模型、假展示和临时文件，不读取真实凭据、不联网、不修改主人的实际备忘录。实窗检查也使用临时样例，输出 `memo-window.png`。架构边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。
