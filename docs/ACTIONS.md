# Meow 的动作系统

动作库只在程序内部维护，不在菜单展示。主人用自然语言发出指令，Meow 也能根据状态自行选择动作。

## 现有动作

| 动作 | 说法示例 | 表现 |
| --- | --- | --- |
| 打滚 | 打个滚、翻一下肚皮 | 缩起身体，侧身翻一周，再站稳 |
| 招手 | 挥挥爪子、招手 | 抬起一只爪子摆动 |
| 点头 | 点点头 | 耳朵与脸轻轻上下移动 |
| 摇头 | 摇摇头 | 耳朵与脸左右摆动 |
| 跳舞 | 跳个舞 | 身体和爪子随节奏摆动 |
| 转圈 | 转一圈 | 原有的两圈旋转动画 |
| 跳跃 | 跳一下 | 物理起跳、落地 |
| 伸懒腰 | 伸个懒腰 | 拉伸、恢复 |
| 过来 | 到我这来 | 跑向鼠标位置 |
| 散步 | 去散个步 | 在当前表面走动 |
| 跳上窗口 | 跳到窗口上去 | 找可达窗口，起跳并站到顶边 |
| 回到地面 | 下来啦 | 从窗口或墙边下来 |
| 玩耍 | 陪我玩一会 | 玩毛线球 |
| 吃东西 | 吃点小鱼干吧 | 进食并增加饱腹值 |
| 睡觉 | 去睡觉吧 | 说完话再入睡 |
| 起床 | 别睡了，起床 | 醒来；贴墙时保持固定 |
| 停下 | 停下、不要打滚 | 停止当前动作与待执行动作 |

另有拖拽挣扎、抛掷、落地压缩、眨眼、耳朵抖动、目光跟随、贴墙探头和情绪效果。这些属于状态动画，无需作为独立指令注册。贴墙时鼠标靠近会弹出身体，用本地固定台词打招呼，移开后缩回，过程中保持固定；睡眠时不触发。

## 一次对话怎样带出动作

1. `ActionLibrary.interpret` 判断本轮话语中的明确要求。按具体说法、主体、否定和上下文过滤；每轮只选一个，不执行故事、引用、假设、知识问题或主人自己的动作。
2. 明确指令优先，立即交给 `PetEngine.requestAction`，不用等待网络。睡觉会等回复结束；空中收到新指令先等落地，新的指令替换待执行项，拖拽清空它。
3. 正常回复仍由当前对话模型生成。系统提示词中的动作目录直接来自注册表，模型可返回一个库内动作标签，也可以不返回。标签从显示文字中去掉。
4. 没有明确要求时，才考虑模型建议的小动作。走动、跳窗、喂食、睡觉等不能只靠模型自行触发；否定或创作任务也不接受模型建议绕过限制。
5. 明确指令已经开始后，不重复执行回复中的标签。动作和聊天共享时钟，但说话不覆盖正在执行的身体动作。网络失败不会撤销已开始的明确动作。

该设计没有增加一次动作分类 API 调用。模型未就绪时，已识别的动作仍有本地回应，未知聊天继续等待模型恢复。

## 空闲时的自主活动

原有活动循环在空闲时考虑散步、跳窗、回到地面等行为；其中的姿态动作改从动作库按状态筛选，再按权重选择，完全在本机完成。

- 精力和心情较好时可打滚、跳舞、转圈或轻跳。
- 主人靠近（鼠标距离或聊天关注状态）时可招手、点头；心情低落时可摇头。
- 疲惫时减少耗体力动作，多伸懒腰；饥饿时不自主打滚或跳舞。
- 安静偏好降低活跃动作权重。窗口顶上不自主打滚；贴墙、睡觉、拖拽、空中和忙碌时不发动新动作。
- 自动动作有全局 8 秒、同动作至少 12 秒冷却；明确指令不受自动冷却限制。

## 怎样增加动作

主要目录是 `Sources/Meow/Pet/ActionLibrary.swift`。每条记录包括协议动作、中文名称、示例说法、别名、动画状态和时长、模型建议权限、是否需要离墙、自动冷却、空闲权重与状态门槛。

增加全新造型时，在 `PetModel.swift` 注册动作和动画状态，在 `PetView.swift` 绘制。简单姿态可直接填入目录的 `pose` 和 `duration`，沿用通用计时执行；涉及真实移动、食物、睡眠等副作用时，在引擎加入对应处理。同步补充意图与执行检查，以及 `Snapshot.swift` 的定格预览。

`ActionSelfTest.swift` 使用隔离 Brain、模拟屏幕和时钟检查指令、模型标签、状态筛选、冷却、停止、拖拽与离墙衔接；不读取 API Key、不调用模型或写入主人数据。
