# 钥匙串反复要求密码

## 先处理当前安装

1. 退出所有正在运行的 Meow。安装磁盘里的应用和“应用程序”中的应用是两个启动位置，旧版本可能同时运行。
2. 将新版复制到 `/Applications/Meow.app`，推出安装磁盘，以后从“应用程序”打开。
3. 如系统请求访问 `com.meow.pet.volcengine`，输入登录钥匙串的密码，并选择“始终允许”。一般是 Mac 登录密码，不是模型密钥或 Apple 账户密码；如果登录钥匙串密码曾单独修改，以该钥匙串的密码为准。
4. 若之前取消了授权，在 Meow 设置中点击“重新授权钥匙串”，读取成功后保存模型设置。

“允许一次”只对本次访问有效，下次访问可能再次询问；“始终允许”会记录对当前应用身份的授权，见 [Apple 钥匙串授权说明](https://support.apple.com/en-tm/guide/keychain-access/kyca1243/11.0/mac/27)。

若同一份已安装版本仍反复提示，可在“钥匙串访问”中搜索 `com.meow.pet.volcengine`，检查该项的“访问控制”，确认允许的应用为 `/Applications/Meow.app`。只调整这个项目的 Meow 权限即可。钥匙串被锁定或密码不同步时，仍需先解决系统钥匙串的解锁问题。

## 1.0.1 的改动

- 启动时合并相同应用标识的实例；从安装盘或另一份应用再次启动时，切回先启动的实例，并在初始化模型前退出新进程。
- 火山方舟密钥的读取结果在进程内共享。启动模型、打开设置、重新加载模型使用同一份结果。
- 授权取消或读取失败也会被记住，不通过重开设置、自动重载来重复触发系统弹窗。明确点击“重新授权钥匙串”才重新读取。
- 保存新密钥成功后直接更新会话缓存，模型重载不再读一次钥匙串。密钥未改动时不重复写入。

密钥仍由系统钥匙串持久保存；会话缓存只存在内存中。微博凭据和信箱身份使用各自独立的钥匙串项目，此处的合并针对火山方舟密钥。

## 为什么更新版本后可能再次询问

本机临时签名以特定二进制版本的摘要作为应用身份，重新编译后的版本可能需要重新授权。应用名称和应用标识相同，并不保证钥匙串把两个版本识别为同一个身份。Apple 对这一点的说明见 [代码签名要求](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。

发布者可在已安装签名证书的 Mac 上指定固定身份：

```sh
MEOW_CODESIGN_IDENTITY='Developer ID Application: 你的证书名称' ./scripts/package_dmg.sh
```

持续使用同一签名身份可以维持版本之间的身份连续性。打包脚本默认仍为本机临时签名，不会自动创建证书、修改钥匙串访问控制或完成 Apple 公证。公证与钥匙串访问授权是两项不同的系统机制。

## 开发检查

```sh
build/Meow.app/Contents/MacOS/Meow --credentials-check
```

检查使用注入的模拟凭据，覆盖重复读取、拒绝后的手动重试、保存后重载、保存失败和实例选择，不访问真实钥匙串，也不请求模型。系统授权窗口仍需在实际安装的应用中确认。

改名升级时，Meow 会在首次读取凭据时将旧服务项导入 `com.meow.pet` 下的对应项。系统可能要求授权访问旧项；模型密钥授权被取消后，本次运行中需在设置中明确重试，才会再次请求授权。信箱沿用原私钥，迁移失败时不会生成新身份。旧项保留作备份；清除新凭据会保留空值标记，防止重新导入。
